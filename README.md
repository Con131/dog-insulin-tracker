# Инсулин-пёс — дневник инъекций и push-напоминания

Приложение: **https://con131.github.io/dog-insulin-tracker/**

Таблица: [Google Таблица](https://docs.google.com/spreadsheets/d/10HzH-zEU-aO1zhxWQqrTx93quhEtbF1nBT7pZuZAT04/edit)

Интерфейс PWA размещён на GitHub Pages, записи хранятся в Google Таблице, доступ к которой оставьте **Ограниченным**. Google Apps Script выступает API, запускается от имени владельца и доступен по секретному URL. Каждый обладатель `/exec` может читать и менять записи — передавайте адрес только доверенным людям. Firebase Cloud Messaging (FCM) отправляет push, когда приложение закрыто; для этого нужен отдельный Firebase-проект.

## 1. Подготовьте закрытую таблицу и Apps Script

1. Войдите в Google под аккаунтом-владельцем таблицы и откройте **Расширения → Apps Script**.
2. Замените содержимое `Code.gs` кодом из [этого файла](https://github.com/Con131/dog-insulin-tracker/blob/main/Code.gs). HTML-файл в Apps Script создавать не нужно.
3. Сохраните изменения. В редакторе выберите `setupTrackingSheet` и нажмите **Выполнить**. Подтвердите доступ к таблице. Скрипт создаст или обновит лист `Инъекции`; прежние записи не удаляются.
4. Позже здесь же запустите `setupPushNotifications` — это создаст скрытый лист для FCM-токенов и таймер-проверку каждые 5 минут.

## 2. Настройте Firebase Cloud Messaging

Firebase Web config и VAPID public key не являются секретами. **Приватный ключ сервисного аккаунта не вводите на сайте и не публикуйте в репозитории.**

1. Создайте проект в [Firebase Console](https://console.firebase.google.com/) или выберите существующий. Добавьте Web App и скопируйте его `firebaseConfig` (объект с `apiKey`, `projectId`, `messagingSenderId`, `appId`).
2. В Firebase откройте **Project settings → Cloud Messaging → Web Push certificates** и нажмите **Generate key pair**. Скопируйте публичный ключ VAPID.
3. В Google Cloud Console для того же Firebase-проекта включите **Firebase Cloud Messaging API**.
4. Создайте сервисный аккаунт Google Cloud для этого проекта, выдайте ему роль **Firebase Cloud Messaging API Admin** и создайте JSON key. Храните скачанный JSON в безопасном месте. Не добавляйте его в GitHub.
5. В Apps Script откройте **Настройки проекта → Свойства скрипта → Добавить свойство**. Имя: `FCM_SERVICE_ACCOUNT_JSON`; значение: всё содержимое JSON key сервисного аккаунта. Сохраните.
6. Запустите `setupPushNotifications` в редакторе Apps Script и разрешите создание триггера. Если Google просит дополнительных разрешений, подтвердите их для своего проекта.

Триггер проверяет срок каждые 5 минут; фактическая доставка может задержаться из-за планировщика Google, сети или настроек энергосбережения. При отправке FCM получает только текст напоминания и URL приложения, не дозу, сахар, автора или историю. FCM-токены устройств хранятся в скрытом листе `PushDevices` этой таблицы.

## 3. Разверните Apps Script API

1. В Apps Script выберите **Развернуть → Новое развертывание → Веб-приложение**.
2. Установите **Выполнять от имени: Я** и **У кого есть доступ: Все (Anyone)**.
3. Разверните и скопируйте URL, оканчивающийся на `/exec`. Его следует считать паролем.
4. Если вы обновляете прежнюю версию, используйте **Управление развертываниями → Изменить → Новая версия → Развернуть**. Чтобы отозвать старую ссылку, архивируйте старое развертывание. URL нового развертывания может измениться.

API поддерживает JSONP для чтения и `POST` с `text/plain` для изменения данных — браузеру не требуется разрешать CORS. Публичный URL API не записан в репозиторий: пользователь вводит его на устройстве.

## 4. Подключите приложение на каждом устройстве

1. Откройте [GitHub Pages](https://con131.github.io/dog-insulin-tracker/), вставьте Apps Script URL `/exec` и нажмите **Подключить и открыть дневник**.
2. В разделе **Защита и хранение данных** вставьте Firebase Web App config как JSON и VAPID public key, затем нажмите **Сохранить настройки**. Эти значения нужно добавить на каждом устройстве; сам Apps Script URL также хранится локально в браузере.
3. Добавьте PWA на главный экран:
   - **Android:** Chrome → меню → **Установить приложение** или **Добавить на главный экран**.
   - **iPhone/iPad:** Safari → **Поделиться → На экран «Домой»**. Web Push на iOS/iPadOS доступен начиная с версии 16.4 и только для PWA, добавленного на экран «Домой».
4. Внизу дневника раскройте меню **Настройки и действия**, нажмите **Включить push-уведомления** и разрешите уведомления. На iPhone разрешение нужно запрашивать из установленного PWA.
5. Для проверки можно дождаться 12 часов после последней записи; Apps Script отправит уведомление в ближайший запуск триггера. Доставка требует, чтобы на устройстве были интернет и разрешение на уведомления.

Уведомление не является точным медицинским таймером и не заменяет расписание ветеринарного врача. Если запись изменена или добавлена более поздняя инъекция, срок считается от неё. Для каждого устройства push нужно включить отдельно.

## Возможности и хранение

- Запись инъекции: дата/время, автор, доза, сахар, зона, приём пищи и примечание; редактирование обновляет строку с тем же ID.
- История, обновление, офлайн-кэш и очередь синхронизации находятся в браузере. Google Таблица остаётся основной копией после синхронизации.
- Напоминание планируется на 12 часов после самой поздней записи. Apps Script проверяет срок независимо от открытого приложения и отправляет FCM push зарегистрированным устройствам.
- Секретный URL Apps Script и локальные записи находятся в хранилище браузера устройства; защищайте телефон блокировкой экрана. Не сохраняйте общую ссылку в публичные закладки.
- Таблицу оставьте с доступом **Ограниченный**. Не включайте «Все, у кого есть ссылка» в настройках самой таблицы.
- Чтобы отозвать доступ, архивируйте развертывание Apps Script и удалите старые push-триггеры/устройства, если они больше не нужны. Записи, которые уже просмотрели, отозвать невозможно.

## Устранение неполадок
- **Не загружается история:** проверьте URL `/exec`, наличие доступа **Anyone**, соединение и выполнение `setupTrackingSheet`.
- **Push не включается:** проверьте Firebase config, VAPID key, HTTPS, включённый Cloud Messaging API и разрешения браузера/ОС. На iOS проверьте, что открыта именно иконка PWA с домашнего экрана.
- **Push не приходит:** убедитесь, что запущен `setupPushNotifications`, в скрытом листе `PushDevices` есть устройство и последняя запись старше 12 часов. В Apps Script откройте **Выполнения**, чтобы посмотреть ошибки таймера/FCM.
- **Утекла ссылка:** немедленно архивируйте развертывание Apps Script, создайте новое и замените URL на всех устройствах.

## Дополнительные возможности

### Автоматическое обновление сервера

После однократной настройки GitHub Actions Apps Script публикуется автоматически при изменении `Code.gs` в `main`. Для обычного обновления не нужно открывать Apps Script или нажимать «Развернуть». URL дневника и таблица остаются прежними. Это не добавляет отдельной платной платформы: сервер остаётся в Apps Script, данные — в Google Таблице, а публикация выполняется GitHub Actions в рамках доступных лимитов GitHub.

Первоначально потребуется помощь владельца Google Apps Script и администратора GitHub:

1. В Apps Script откройте **Настройки проекта** и скопируйте **Идентификатор скрипта**. В **Развернуть → Управление развертываниями** найдите ID активного веб-приложения (это не URL `/exec`).
2. Включите [Google Apps Script API](https://script.google.com/home/usersettings). Установите [Node.js 22](https://nodejs.org/), откройте PowerShell и выполните:

   ```powershell
   npm install --global @google/clasp@3.4.1
   clasp login
   ```

   Войдите в Google-аккаунт владельца скрипта и разрешите доступ. Файл `.clasprc.json` в профиле Windows содержит доступ к Google — не отправляйте его и не добавляйте в проект.
3. В GitHub откройте репозиторий → **Settings → Environments → New environment**, назовите его `apps-script-production`.
4. В этом окружении добавьте три **Environment secrets**:
   - `CLASP_CREDENTIALS` — полный текст файла `.clasprc.json`;
   - `CLASP_SCRIPT_ID` — ID скрипта из шага 1;
   - `CLASP_DEPLOYMENT_ID` — ID действующего веб-приложения из шага 1.
5. Проверьте настройку: GitHub → **Actions → Deploy Apps Script → Run workflow**, ветка `main`. Зелёный результат означает, что публикация прошла.

После этого для обновления достаточно изменить `Code.gs` в GitHub и сохранить изменение в `main`. Если GitHub предлагает сделать pull request, создайте его и объедините; после этого публикация запустится сама. Результат виден во вкладке **Actions**. Также workflow можно запустить вручную через **Run workflow**.

Не выдавайте право записи в репозиторий посторонним: редактор кода может менять сервер. OAuth-файл и Firebase private key нельзя размещать в PWA, коде или коммитах. Secrets доступны только процессу публикации, но не посетителям приложения. Workflow загружает код из репозитория; свойства Apps Script (`FCM_SERVICE_ACCOUNT_JSON`), триггеры, таблица и записи остаются на месте.

### Обновление приложения на телефоне

Внизу страницы откройте меню **Настройки и действия** и нажмите **Проверить обновления приложения**. PWA загрузит свежую оболочку с GitHub Pages и перезапустится. Обновление интерфейса не публикует код Apps Script.
