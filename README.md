# Инсулин-пёс — дневник инъекций

PWA для размещения на GitHub Pages. Интерфейс целиком находится в `index.html`; `manifest.json`, `sw.js` и `icon.svg` нужны браузеру для установки приложения и кеширования оболочки. Серверная часть для Google Таблиц — `Code.gs`.

Опубликованное приложение: **https://con131.github.io/dog-insulin-tracker/**. Для хранения данных скрипт уже настроен на ID предоставленной таблицы; отдельный скрипт-развертывание Google Apps Script нужно создать от имени владельца таблицы.

## Быстрый запуск

1. Откройте предоставленную Google Таблицу под аккаунтом, который имеет право её редактировать.
2. В таблице откройте **Расширения → Apps Script**, удалите примерный код и вставьте содержимое `Code.gs`. ID таблицы уже прописан в файле; менять его не нужно.
3. Сохраните проект. В списке функций выберите `setupTrackingSheet` и нажмите **Выполнить**. При первом запуске Google попросит разрешить скрипту доступ к таблице. На листе `Инъекции` появятся заголовки; другие листы таблицы не затрагиваются.
4. Нажмите **Развернуть → Новое развертывание**. Выберите тип **Веб-приложение**; «Выполнять от имени» — **Я**, доступ — **Все**. Нажмите **Развернуть** и подтвердите разрешения.
5. Скопируйте URL веб-приложения, оканчивающийся на `/exec` (не `/dev`). В приложении откройте **Настройки подключения**, вставьте URL и сохраните.
6. Приложение уже опубликовано по HTTPS на GitHub Pages; после изменений сайта GitHub обновит его из `main`.
7. На телефоне откройте сайт и выберите **Добавить на экран «Домой»** / **Установить приложение**.

## Как получить URL Google Apps Script

URL появляется в окне результата после шага **Развернуть → Новое развертывание → Веб-приложение**. Обычно он выглядит как `https://script.google.com/macros/s/AKfycb.../exec`. Если код менялся после публикации, откройте **Развернуть → Управление развертываниями**, выберите развертывание, нажмите редактирование и выберите новую версию — ссылка при этом сохраняется.

## Синхронизация и ограничения Google Apps Script

- История и очередь ожидающих отправки записей сначала сохраняются в `localStorage` этого браузера; запись сразу видна в интерфейсе. Когда сеть доступна, приложение отправляет очередь и читает таблицу для подтверждения. Не закрывайте страницу до завершения синхронизации, если запись должна немедленно попасть в таблицу. При отсутствии сети очередь повторится при следующем открытии приложения или возвращении соединения.
- Идентификатор записи защищает от дублирования при повторной отправке. Данные локального хранилища не синхронизируются между браузерами; общими для устройств становятся только записи, дошедшие до таблицы.
- У Google Apps Script `ContentService` нет API для установки произвольного `Access-Control-Allow-Origin`. Поэтому в этом проекте чтение работает через JSONP, а запись отправляется как `text/plain` без CORS preflight и затем подтверждается чтением. Это не добавляет несуществующие CORS-заголовки и позволяет клиенту GitHub Pages обращаться к опубликованному скрипту. `doGet` также поддерживает обычный JSON-ответ без параметра `callback`.
- Для доступа из браузера скрипт должен быть опубликован с доступом **Все**. Следовательно, любой человек, получивший URL, может прочитать записи и отправлять записи. URL не является секретом или системой авторизации; не храните в такой таблице данные, которые должны оставаться приватными. Если необходима аутентификация, используйте защищённый серверный API.
- Таймер — только напоминание, отсчитывающее 12 часов от самой поздней записи. Он не является медицинской рекомендацией. Уточняйте дозы и расписание у ветеринарного врача.

## Данные

`doPost` принимает JSON-объект вида:

```json
{
  "id": "уникальный-id",
  "injectedAt": "2026-10-24T19:30:00.000Z",
  "dose": 2.5,
  "glucose": 8.2,
  "site": "Холка",
  "meal": "Съела всё",
  "note": "Примечание"
}
```

Поле `glucose` можно передать пустой строкой. `doGet` возвращает `{ "entries": [...] }` от новых записей к старым; для чтения между доменами поддерживается JSONP-параметр `callback`.
